# anvil

**anvil** es un *AI Engineering Harness* nativo en Rust diseñado para **Antigravity** y **Claude Code**.

Compilado en un único binario nativo sin dependencias externas de runtime, **anvil** impone ingeniería determinista sobre el ciclo de trabajo de agentes de IA: verificación por niveles, análisis estático AST multi-lenguaje, grafo de código incremental, memoria persistente con divulgación progresiva, seguimiento automático de tareas en equipo y control estricto de presupuesto de tokens.

## Visión General

En lugar de depender de instrucciones largas en prompts o verificaciones manuales propensas a olvidos, **anvil** mantiene `.harness/` como única fuente de verdad del repositorio y conecta el entorno del agente mediante hooks de ciclo de vida y un servidor MCP unificado.

- **Multi-lenguaje y multi-repo:** soporta TypeScript/JavaScript, React, Angular, NestJS, Next.js, Astro, Vite, Python, Kotlin/Android, Flutter/Dart, Rust y PHP 8.x / Laravel (API, Blade, Inertia y Livewire), tanto en repositorios simples como en monorepos y espacios de trabajo *umbrella*.
- **Economía de tokens:** lee firmas y símbolos concretos antes de archivos completos, bloquea lecturas accidentales de lockfiles/vendor/bundles y comprime logs de compiladores y tests a resúmenes acotados.
- **Cero suposiciones no verificadas:** combina análisis AST determinista, trazado de origen (*blast radius* inverso) y verificación real de herramientas nativas del proyecto.

## Capas del Harness

### 1. Capa de Núcleo y Control Operativo (`anvil-core`)
Define la configuración del repositorio (`.harness/config.json`), la detección automática de stacks y herramientas, el clasificador semántico de diffs (documentación, estilos, configuración, lógica, contratos, UI y dependencias), el compresor de salida de comandos, la caché por contenido (`blake3`), la telemetría local, el **Circuit Breaker (`N=3`)** contra reintentos ciegos y el motor **Ratchet** para graduar errores recurrentes en reglas deterministas con aprobación humana.

### 2. Capa AST y Reglas Tier 0 (`anvil-ast`)
Integra gramáticas `tree-sitter` embebidas en un recorrido de una sola pasada para extraer símbolos, rangos de líneas, relaciones y contratos HTTP/templates, mientras ejecuta reglas deterministas instantáneas (`< 500 ms`): bloqueo de *escape hatches* sin `anvil-allow`, comentarios diferidos/narrativos, higiene de tipos estrictos (`any`, `dynamic`, `declare(strict_types=1)`), higiene Laravel/PHP, archivos *barrel* puros, higiene de raíz y verificación de permisos.

### 3. Capa de Grafo de Código e Impacto Tier 1 (`anvil-graph`)
Mantiene un índice binario incremental y paralelo del código fuente, resolviendo módulos e imports nativos (TSConfig, Angular, NestJS, Python, Kotlin/Gradle, Dart, Rust/Cargo, PHP PSR-4, Blade/Inertia/Livewire y rutas HTTP cross-stack). Permite consultar impacto inverso (*reverse-BFS blast radius*), rastrear el origen real de un símbolo, leer solo el bloque exacto de un símbolo o su esquema de firmas, y ejecutar *typecheckers* y tests nativos únicamente sobre los archivos afectados.

### 4. Capa de Memoria Persistente (`anvil-memory`)
Combina SQLite FTS5 local con fragmentos JSONL amigables con Git (`.harness/memory/chunks/`) bajo un modelo de divulgación progresiva (*search → timeline → get*), con redacción automática de secretos y validación de vigencia contra el grafo de código vivo.

### 5. Capa de Verificación Tier 2 (`anvil-deps` y `anvil-qa`)
- **Auditoría de dependencias (`anvil-deps`):** analiza manifiestos de npm, PyPI, pub.dev, Maven, Cargo y Composer/Packagist para detectar paquetes deprecados, abandonados o sin mantenimiento (>24 meses) con caché TTL.
- **QA Visual Híbrido (`anvil-qa`):** combina inspecciones programáticas de DOM y árbol de vistas móvil (Playwright, Chrome DevTools, ADB/`uiautomator`, `logcat` y Roborazzi) con capturas *antes/después*.

### 6. Capa de Tareas sin Conflictos (`anvil-tasks`)
Registra automáticamente el trabajo en curso al primer archivo editado y gestiona un libro mayor de tareas distribuido por autor y ULID (`.harness/tasks/` → `tasks.json`) con driver de merge para Git, evitando conflictos entre desarrolladores y agentes concurrentes.

### 7. Capa de Adaptadores, MCP y CLI (`anvil-adapters`, `anvil-mcp`, `anvil-cli`)
- **Adaptadores finos (`anvil-adapters`):** traducen eventos de ciclo de vida (`SessionStart`, `PreInvocation`, `PreToolUse`, `PostToolUse`, `Stop`), *Token Guard* y configuración sincronizada para **Antigravity** y **Claude Code**.
- **Servidor MCP unificado (`anvil-mcp`):** expone herramientas de grafo y memoria sobre `stdio` JSON-RPC 2.0.
- **CLI y Daemon (`anvil-cli`):** interfaz principal con salida estructurada y un daemon TCP local opcional que mantiene el grafo caliente en memoria.
