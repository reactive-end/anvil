# Anvil

**Anvil** is a native Rust AI engineering harness built for **Antigravity**, **Claude Code**, **Cursor**, **Windsurf**, and **Codex**.

Packaged as a single native binary with zero external runtime dependencies, **Anvil** enforces deterministic engineering discipline across AI-assisted workflows: tiered verification, multi-language AST analysis, an incremental code graph, sandboxed **Code Mode**, progressive-disclosure persistent memory, conflict-free team task tracking, and strict token-budget control.

## Overview

Instead of relying on bloated prompt instructions or manual verification habits, **Anvil** keeps `.harness/` as the repository's single source of truth and wires directly into the agent lifecycle through thin adapters, hooks, interactive terminal setup, and a unified MCP server.

- **Multi-language & multi-repo:** supports TypeScript/JavaScript, React, Vue/Svelte SFC, Angular, NestJS, Next.js, Astro, Vite, Python, Kotlin/Android, Flutter/Dart, Rust, PHP 8.x / Laravel (API, Blade, Inertia, and Livewire), and **Godot 4** (GDScript, `.tscn`, `.gdshader`) across single repositories, monorepos, and thin-umbrella multi-repo workspaces.
- **Token-efficient & Code Mode enabled:** inspects symbol outlines and exact AST slices before reading full files, runs chained read-only queries inside a pure-Rust JS sandbox (`code_exec` / `anvil code exec`), wraps external MCPs behind `anvil mcp --proxy`, guards against reading lockfiles/bundles whole, and compresses compiler/test output into bounded summaries.
- **Evidence-first verification:** combines deterministic AST checks, anti-test-tampering diff guards, reverse blast-radius analysis, architecture boundary/cycle rules, opt-in local **SonarQube** integration, and scoped execution of native typecheckers and test runners.

## Harness Layers (11 Crates)

### 1. Core & Operational Control (`anvil-core`)
Manages repository configuration (`.harness/config.json`), `.gitignore`-aware stack and tool detection, semantic diff classification (`docs`, `style`, `config`, `logic`, `contracts`, `UI`, `deps`), token-bounded output compression, content-addressed Tier 1 check caching (`blake3`), anti-test-tampering diff analysis (`no-test-tampering`), opt-in local **SonarQube** Web API & complexity checks, an always-on Tier 0 check that rejects added lines duplicating existing code (`anvil-allow(duplication): <reason>`), trajectory telemetry (`anvil stats --trajectories`), the **`N=3` Circuit Breaker** against blind retries, and the **Ratchet** engine for graduating recurring mistakes into deterministic rules (`--severity error|warn|info`, automatic `fp_checked` verification in `anvil ratchet test`, and human-approved promotion).

### 2. AST & Tier 0 Rules (`anvil-ast`)
Embeds `tree-sitter` grammars in a single-pass parser pool (plus dedicated Vue/Svelte SFC and Godot 4 `.gd`/`.tscn`/`.gdshader` parsers) to extract symbols, line spans, call/import edges, HTTP routes, and template references while running sub-second deterministic Tier 0 checks: blocking unapproved escape hatches, deferred/narrative comments, strict-type violations (`any`, `dynamic`, `declare(strict_types=1)`), PHP/Laravel & Godot hygiene issues, pure barrel re-exports, root hygiene violations, and unverified permission assumptions.

### 3. Code Graph & Tier 1 Impact (`anvil-graph`)
Maintains a parallel, incremental binary code graph (`postcard`) with native resolution across TSConfig, Angular, NestJS, Python, Kotlin/Gradle, Dart, Rust/Cargo, PHP PSR-4, Blade/Inertia/Livewire, Godot scenes/autoloads, and cross-stack HTTP routes. Powers reverse-BFS blast radius, upstream origin tracing, architecture boundary & circular-import checks, signature-only outlines, targeted symbol reads, and scoped Tier 1 typecheck and test execution (including native `node --test` alongside `vitest`/`jest` and language-native runners).

### 4. Persistent Memory (`anvil-memory`)
Combines local SQLite FTS5 indexing with Git-friendly JSONL chunks (`.harness/memory/chunks/`) using progressive disclosure (*search → timeline → get*), automatic secret redaction, and staleness detection tied to the live code graph.

### 5. Sandboxed Code Mode (`anvil-codemode`)
Embeds a pure-Rust JavaScript engine (`boa_engine`) enabling agents and CLI users to batch, filter, and transform multiple read-only Anvil MCP calls in a single round-trip (`code_exec`, `anvil code exec`), or compress external stdio MCP servers via `anvil mcp --proxy` (`proxy_search` + `proxy_exec` with mutation guards and secret redaction).

### 6. Tier 2 Verification (`anvil-deps` & `anvil-qa`)
- **Dependency Auditing (`anvil-deps`):** audits npm, PyPI, pub.dev, Maven, Cargo, and Composer/Packagist manifests for deprecated, abandoned, >24-month stale packages, and **OSV.dev** vulnerabilities with TTL caching.
- **Hybrid Visual QA (`anvil-qa`):** pairs programmatic Web DOM and Mobile view-tree checks (Playwright, Chrome DevTools, ADB/`uiautomator`, `logcat`, Roborazzi, and headless Godot GUT/render QA) with before/after visual verification.

### 7. Conflict-Free Task Ledger & Feature Lists (`anvil-tasks`)
Tracks tasks with short sequential codes (`T-001`, `T-002`, ...) or 1-level grouped directories (`.harness/tasks/<group>/<ID>/` via `--group`/`--flat` or `--id F039`), immutable per-author ULID entries, and crash-safe per-task `progress.md` checkpoints. Root `tasks.json` is kept as a compact v2 index pointing to `.harness/tasks/<ID>/progress.md` (without duplicating `entries` or `files_touched`), backed by a Git merge driver (`anvil tasks merge-driver`) — teams wanting zero root PR churn can optionally add `tasks.json` to `.gitignore` with zero runtime impact. Also supports strictly single-task execution and interruption recovery (`anvil tasks start|update|done|resume`, `SessionStart` Resume Briefs), decomposing monolithic `feature_list.json` requirement lists (`anvil tasks import` with native OS / arrow-key TUI file browser), verifying `verify` commands (`anvil tasks verify --record`), exporting snapshots (`anvil tasks export`), migrating legacy IDs (`anvil tasks migrate-ids`), and full MCP lifecycle tools (`task_start`, `task_update`, `task_done`, `task_resume`, `task_list`, `task_get`).

### 8. Adapters, MCP Server & CLI (`anvil-adapters`, `anvil-mcp`, `anvil-cli`)
- **Thin Adapters (`anvil-adapters`):** translate lifecycle hooks (`SessionStart`, `PreInvocation`, `PreToolUse`, `PostToolUse`, `Stop`), **Security Guard**, **Token Guard**, **Availability Guard** (gracefully skips `anvil:managed` blocks when `anvil` is absent from `PATH`), and synced configs/rules for Antigravity, Claude Code, Cursor, Windsurf, and Codex (including thin-umbrella multi-repo routing).
- **Unified MCP Server (`anvil-mcp`):** exposes 23 code-graph, memory, task, review, and Code Mode tools over `stdio` JSON-RPC 2.0, plus `--proxy` gateway mode.
- **CLI & Daemon (`anvil-cli`):** provides interactive arrow-key Clack-style TUI initialization (`anvil init`), Git ref snapshots (`anvil checkpoint`), isolated agent worktrees (`anvil worktree`), spec contracts (`anvil spec`), opt-in SonarQube commands (`anvil sonar`), a Claude Code orchestrator/executor model pair (`anvil orchestrator`), diagnostics (`anvil doctor`), and an optional resident TCP daemon.

## Quick Start

```bash
# Build & install the native binary
cargo install --path crates/anvil-cli

# Interactive setup (single repo, monorepo, or thin-umbrella multi-repo + opt-in SonarQube)
anvil init

# Verify changes (Tier 0 AST + Tier 1 blast-radius/typecheck/tests + Tier 2 QA/deps)
anvil check

# Crash-safe task lifecycle & feature_list.json import
anvil tasks import
anvil tasks start <ID|title>
anvil tasks resume

# Query the codebase in one sandboxed JS call via Code Mode
anvil code exec "return anvil.graph_query({ term: 'init', limit: 5 });"

# Claude Code: pair a planning model with a cheaper execution model (model + effort each)
anvil orchestrator setup
anvil orchestrator on               # enforce roles: the orchestrator judges, executors write within SCOPE
anvil orchestrator tools            # choose which of your MCP servers executors load (or --add postgres,chrome-devtools)

# Executor model and effort selector above the Claude Code prompt (the orchestrator uses the native picker)
anvil plugin install

# Record problems review finds after `anvil check` was green; `anvil stats` reports the escape rate per category
anvil review log "unchecked input" --category error-handling --severity high --file src/a.rs:10
anvil review list --since 7

# Optional local SonarQube status & repo health check
anvil sonar status
anvil doctor
```

## Safety Model

Anvil hooks only deny, ask, or stay silent. They never approve a tool call, so the permission system of the host stays in charge. The Security Guard inspects command text (including wrappers, nested shells, substitutions, here-documents, and PowerShell) as a safety net against accidents. It is not a sandbox: scripts on disk and dynamically built commands are outside its reach.

Tier 1 has a latency target (`tier_budgets.tier1_secs`) and a separate hard limit per process (`tier_budgets.tier1_timeout_secs`, 300 by default). Runs that hit the limit are reported as `TIMEOUT`.

## Orchestrator Mode

While the mode is on, Anvil hooks enforce the roles in Claude Code. The main thread inspects, verifies, and delegates, but cannot edit files or write through the shell. `anvil-executor` is the only role that writes, limited to the `SCOPE:` paths of its own latest brief, and cannot commit, manage tasks, or spawn agents. Several executors can run at once: each one's scope is read from its own Claude Code transcript, a brief whose scope overlaps a running or starting executor is refused, and `anvil check --scope <paths>` verifies one executor's files. Agents cannot turn the mode off. File tools and visible shell writes are checked; a program the executor runs can still write elsewhere, so the orchestrator reviews the diff. Executors load only the tools they need to search, edit, build, test, and read docs, plus the Anvil MCP tools, which keeps each one's starting context small; `anvil orchestrator tools` lists the MCP servers Claude Code is configured with (project, local, user, and enabled plugins) and stores the ones you pick in `orchestrator.executor_tools`; `--add` also takes servers the desktop app adds by itself. The mode is enforced in Claude Code only; other tools working in the same repository are not affected.
